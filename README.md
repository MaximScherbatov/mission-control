# Mission Control by CityMetrics

Работающий прототип единого рабочего места для предварительного планирования, экономического сравнения и календарного назначения групповых миссий БВС. Он связывает контур работ, полезную нагрузку, возможности флота, воздушные ограничения и стоимость в объяснимый производственный план.

**Граница применения:** сервис не выдаёт разрешений на полёт и не создаёт исполняемых команд конкретного автопилота. Перед реальным вылетом необходимы проверка актуальных аэронавигационных данных, погоды, рельефа, площадки и паспортных ограничений БВС, а также предусмотренные процедуры согласования.

В текущей версии реализованы:

- map-first интерфейс центра управления;
- рисование площадного контура и поддерживаемой линейной трассы, импорт GeoJSON, KML, GPX и CSV;
- авторизация и роли `dispatcher`, `manager`, `admin`;
- начальные справочники из 10 БВС, шести полезных нагрузок и восьми площадок (состав площадок на сервере может меняться в базе);
- расчёт совместимости БВС и оптики;
- расчёт высоты съёмки, полосы захвата и шага галсов;
- построение галсов по произвольному полигону;
- три объяснимых сценария: «Быстрый», «Минимум налёта» и «Сбалансированный»;
- предварительная стоимость с учётом моточасов, энергии, экипажа, батарей, ТО и подготовки;
- контролируемая WebSocket-симуляция телеметрии;
- реестр заказчиков и сквозной бизнес-процесс заказа от заявки до выдачи результата;
- автозаполнение реквизитов организации через DaData с ручным резервным режимом;
- атомарная передача согласованного заказа в планировщик и серверный календарь;
- оперативная погода, оценка риска, погодные эффекты и анимированный радар осадков;
- приборная панель выбранного БВС с работающим авиагоризонтом;
- необязательный слой внешнего воздушного движения ADS-B/MLAT с резервированием источников;
- карта OpenFreeMap без API-ключа;
- календарь заданий, контроль доступности бортов и суточный план;
- справочник запретных и опасных зон, зон ответственности ОрВД и пользовательских препятствий;
- импорт GeoJSON, ручной ввод координат и рисование ограничений на карте;
- проверка доступных сведений о высоте и времени действия зон, буферы и горизонтальный обход препятствий и кешированных полигонов населённых пунктов, разнесение стартов нескольких БВС;
- экспорт рассчитанных маршрутов в KML, GeoJSON и GPX;
- Docker Compose с PostgreSQL/PostGIS и отдельным SQLite-кешем населённых пунктов.

Маршрут рассчитывается преимущественно в горизонтальной плоскости. Полноценная 3D/4D-проверка по рельефу, вертикальный обход зон, юридическое подтверждение границ OSM и автоматическое получение разрешений **не реализованы**. Параметры части БВС и нагрузок учебные, а стоимость не является коммерческой офертой. Оптимизатор использует объяснимые инженерные правила, а не обученную ML-модель.

## Локальная демонстрация

Для проверки жюри не нужны домен, Caddy или внешняя Docker-сеть:

```bash
docker compose -f docker-compose.jury.yml up -d --build
```

После готовности контейнеров откройте <http://127.0.0.1:8080> и войдите как `dispatcher / dispatcher`. Учебные пароли `manager` и `admin` также совпадают с логинами. **Не публикуйте конкурсный Compose в интернете:** его значения по умолчанию предназначены только для локального стенда. SQLite-кеш населённых пунктов в этой конфигурации находится внутри контейнера API и может быть утрачен при его пересоздании.

Актуальная документация: [техническое описание сервиса](docs/SERVICE_TECHNICAL_DOCUMENTATION.md), [руководство диспетчера](docs/DISPATCHER_USER_GUIDE.md), [методика расчёта](docs/planning-methodology.md) и [развёртывание на сервере](deploy/README.md). [`docs/TECHNICAL_OVERVIEW_AND_LOCAL_DEPLOYMENT.md`](docs/TECHNICAL_OVERVIEW_AND_LOCAL_DEPLOYMENT.md) сохранён как историческое описание раннего стенда; при расхождении ориентируйтесь на текущий код и новые документы.

## Развёртывание с Caddy

Для серверного развёртывания подготовлен адрес `mission.citymetrics.moscow`. Основной Compose подключает веб-контейнер к существующей внешней сети `web`; API и база данных не публикуют порты. API получает отдельную сеть `mission_egress` для исходящих запросов к внешним источникам. Нужны заполненный `.env` и постоянные тома PostgreSQL и SQLite-кеша.

```bash
cp .env.example .env
docker network inspect web >/dev/null 2>&1 || docker network create web
docker compose up -d --build
```

Добавьте блок из `deploy/Caddyfile.mission-control` в основной Caddyfile. Полная инструкция, включая DNS, проверку и резервное копирование: [`deploy/README.md`](deploy/README.md).

Демонстрационные пользователи:

| Роль | Логин | Пароль |
| --- | --- | --- |
| Диспетчер | `dispatcher` | `dispatcher` |
| Руководитель | `manager` | `manager` |
| Администратор | `admin` | `admin` |

Основной Compose не запустится без явной установки `POSTGRES_PASSWORD`, `JWT_SECRET` и паролей пользователей. Для HTTPS предусмотрено `COOKIE_SECURE=true`. Не копируйте демонстрационные пароли на публичный сервер. При обновлении не выполняйте `docker compose down -v`: `-v` удаляет тома с данными.

Для временного локального доступа без Caddy:

```bash
docker compose -f docker-compose.yml -f docker-compose.local.yml up -d --build
```

Интерфейс будет доступен только на <http://127.0.0.1:8080>. Для этого режима в `.env` установите `COOKIE_SECURE=false` и `ALLOWED_ORIGINS=http://127.0.0.1:8080`.

## Устойчивость внешних источников

Публичный ADS-B не является зависимостью критического пути. Основная телеметрия миссии поступает от контролируемого адаптера или встроенного симулятора. В «Центре полётов» диспетчер может включить отдельный слой внешнего движения; его отказ не останавливает планирование или демонстрацию.

Если `AIRCRAFT_CACHE_TTL_SECONDS` оставлен пустым, сервис сам выбирает безопасный интервал: 240 секунд для анонимного OpenSky, 25 секунд при наличии `OPENSKY_CLIENT_ID` и `OPENSKY_CLIENT_SECRET` и 3 секунды для явно выбранного локального `readsb`. Между пакетами браузер плавно прогнозирует положение по путевой скорости и курсу, но не дальше 30 секунд от последней координаты. Свой приёмник readsb/dump1090 имеет приоритет, если заполнен `READSB_URL`; для действительно частого режима укажите `AIRCRAFT_SOURCE=readsb`. Источник airplanes.live выключен, поскольку теперь требует предварительного согласования проекта; после получения доступа установите `AIRPLANES_LIVE_ENABLED=true`.

Подложка по умолчанию — OpenFreeMap Liberty. Она не требует регистрации или API-ключа. Архитектура допускает замену URL стиля на собственный сервер тайлов без изменений бизнес-логики.

Полигоны населённых пунктов загружаются из OSM/Overpass в локальный кеш в фоне; расчёт маршрута использует уже сохранённые границы и не должен ожидать ответа Overpass. Отсутствие или неполнота покрытия требует отдельной проверки и не означает свободное воздушное пространство. Подготовленный файл `backend/app/data/airspace/geoscan_height_obstacles_primorsky.geojson` не входит в текущую автоматическую загрузку начальных зон. Ранее сохранённые записи не исчезают при обновлении кода: порядок адресной очистки после резервного копирования приведён в [серверной инструкции](deploy/README.md).

## API

- `POST /api/auth/login` — вход и выдача HttpOnly-сессии;
- `GET /api/auth/me` — текущий пользователь;
- `GET /api/catalog/uavs` — справочник БВС;
- `GET /api/catalog/optics` — справочник камер и сенсоров;
- `GET /api/catalog/payloads` и `GET /api/catalog/technologies` — нагрузки и технологические профили;
- `GET/POST/PUT/DELETE /api/catalog/bases` — взлётно-посадочные пункты;
- `GET/POST /api/orders` — реестр и регистрация заказов;
- `PATCH /api/orders/{id}/status` — управляемый переход заказа по бизнес-процессу;
- `GET/POST /api/schedule` — серверное расписание с проверкой занятости БВС;
- `POST /api/schedule/batch` — атомарное назначение группы БВС;
- `GET /api/integrations/dadata/suggest` — подсказки по организациям и ИНН;
- `GET /api/weather/forecast` — прогноз и оценка погодного риска;
- `GET /api/weather/radar` — манифест анимации радара осадков;
- `GET /api/traffic/aircraft` — нормализованный внешний ADS-B/MLAT-трафик с кешем и диагностикой источников;
- `GET /api/airspace/summary` — статистика нормативного справочника;
- `GET /api/settlements/coverage` и `GET /api/settlements/polygons` — состояние кеша и границы населённых пунктов;
- `GET/POST/PUT/DELETE /api/airspace/zones` — поиск, импорт и ведение пользовательских зон;
- `GET/PUT /api/airspace/authorities` — справочник контактов и порядка взаимодействия с ОрВД;
- `POST /api/missions/optimize` — расчёт трёх планов;
- `GET /api/missions` — история сохранённых расчётов;
- `GET /api/missions/{id}/flight-plan` — структурированный план с этапами полёта;
- `GET /api/missions/{id}/export?format=kml|geojson|gpx&plan=economy` — выгрузка маршрута выбранного плана;
- `WS /api/telemetry/ws` — демонстрационная телеметрия;
- `GET /api/health` — состояние сервиса и интеграций.

Интерактивная документация API доступна на `/docs`.

## Направления развития

1. Подключить подтверждённые нормативные источники и управляемые разрешительные процедуры.
2. Разработать полноценную 3D/4D-проверку по рельефу и достоверные паспортные энергетические модели.
3. Вести фактические журналы ТО, батарей и состояния флота; расширить промышленную ролевую модель.
4. Подключить корпоративный почтовый/ЭДО-контур и клиентский кабинет к заявкам.
5. Подготовить проверяемый экспорт под конкретные наземные станции управления и перепланирование по фактической телеметрии.
