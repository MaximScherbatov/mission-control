# Mission Control by CityMetrics

Интеллектуальная система планирования, экономической оптимизации и контроля групповых миссий БВС.

Текущая версия — первый сквозной срез:

- map-first интерфейс центра управления;
- ручное рисование территории и импорт GeoJSON;
- авторизация и роли `dispatcher`, `manager`, `admin`;
- справочники из восьми БВС, шести полезных нагрузок и трёх площадок;
- расчёт совместимости БВС и оптики;
- расчёт высоты съёмки, полосы захвата и шага галсов;
- построение галсов по произвольному полигону;
- три объяснимых плана: быстрый, экономичный и надёжный;
- стоимость с учётом моточасов, энергии, экипажа, батарей, ТО и риска;
- контролируемая WebSocket-симуляция телеметрии;
- реестр заказчиков и сквозной бизнес-процесс заказа от заявки до выдачи результата;
- автозаполнение реквизитов организации через DaData с ручным резервным режимом;
- атомарная передача согласованного заказа в планировщик и серверный календарь;
- оперативная погода, оценка риска, погодные эффекты и анимированный радар осадков;
- приборная панель выбранного БВС с работающим авиагоризонтом;
- необязательный слой внешнего воздушного движения ADS-B/MLAT с резервированием источников;
- карта OpenFreeMap без API-ключа;
- календарь заданий, контроль доступности бортов и суточный план;
- справочник запретных и опасных зон, зон ответственности ОрВД и пользовательских препятствий;
- импорт GeoJSON, ручной ввод координат и рисование ограничений на карте;
- предполётная проверка по высоте и времени, безопасные буферы, обход внешних препятствий и разнесение стартов нескольких БВС;
- экспорт рассчитанных маршрутов в KML, GeoJSON и GPX;
- полностью автономный Docker Compose с PostgreSQL/PostGIS.

## Конкурсный локальный запуск


```bash
docker compose -f docker-compose.jury.yml up -d --build
```

После готовности контейнеров откройте <http://localhost:8080> и войдите как `dispatcher / dispatcher`.

Актуальная документация: [техническое описание сервиса](docs/SERVICE_TECHNICAL_DOCUMENTATION.md), [руководство диспетчера](docs/DISPATCHER_USER_GUIDE.md). Инструкция по локальному развёртыванию остаётся в [`docs/TECHNICAL_OVERVIEW_AND_LOCAL_DEPLOYMENT.md`](docs/TECHNICAL_OVERVIEW_AND_LOCAL_DEPLOYMENT.md); её старые продуктовые формулировки не следует использовать вместо актуального описания.


## Демонстрационные пользователи:

| Роль | Логин | Пароль |
| --- | --- | --- |
| Диспетчер | `dispatcher` | `dispatcher` |
| Руководитель | `manager` | `manager` |
| Администратор | `admin` | `admin` |

Compose не запустится без явной установки `POSTGRES_PASSWORD`, `JWT_SECRET` и демонстрационных паролей. Для HTTPS уже предусмотрено `COOKIE_SECURE=true`.

Для временного локального доступа:

```bash
docker compose -f docker-compose.yml -f docker-compose.local.yml up -d --build
```

Интерфейс будет доступен только на <http://127.0.0.1:8080>. Для этого режима в `.env` установите `COOKIE_SECURE=false` и `ALLOWED_ORIGINS=http://127.0.0.1:8080`.

## Устойчивость внешних источников

Публичный ADS-B не является зависимостью критического пути. Основная телеметрия миссии поступает от контролируемого адаптера или встроенного симулятора. В «Центре полётов» диспетчер может включить отдельный слой внешнего движения; его отказ не останавливает планирование или демонстрацию.

Если `AIRCRAFT_CACHE_TTL_SECONDS` оставлен пустым, сервис сам выбирает безопасный интервал: 240 секунд для анонимного OpenSky, 25 секунд при наличии `OPENSKY_CLIENT_ID` и `OPENSKY_CLIENT_SECRET` и 3 секунды для явно выбранного локального `readsb`. Между пакетами браузер плавно прогнозирует положение по путевой скорости и курсу, но не дальше 30 секунд от последней координаты. Свой приёмник readsb/dump1090 имеет приоритет, если заполнен `READSB_URL`; для действительно частого режима укажите `AIRCRAFT_SOURCE=readsb`. Источник airplanes.live выключен, поскольку теперь требует предварительного согласования проекта; после получения доступа установите `AIRPLANES_LIVE_ENABLED=true`.

Подложка по умолчанию — OpenFreeMap Liberty. Она не требует регистрации или API-ключа. Архитектура допускает замену URL стиля на собственный сервер тайлов без изменений бизнес-логики.

## API

- `POST /api/auth/login` — вход и выдача HttpOnly-сессии;
- `GET /api/auth/me` — текущий пользователь;
- `GET /api/catalog/uavs` — справочник БВС;
- `GET /api/catalog/optics` — справочник камер и сенсоров;
- `GET /api/catalog/bases` — взлётно-посадочные пункты;
- `GET/POST /api/orders` — реестр и регистрация заказов;
- `PATCH /api/orders/{id}/status` — управляемый переход заказа по бизнес-процессу;
- `GET/POST /api/schedule` — серверное расписание с проверкой занятости БВС;
- `GET /api/integrations/dadata/suggest` — подсказки по организациям и ИНН;
- `GET /api/weather/forecast` — прогноз и оценка погодного риска;
- `GET /api/weather/radar` — манифест анимации радара осадков;
- `GET /api/traffic/aircraft` — нормализованный внешний ADS-B/MLAT-трафик с кешем и диагностикой источников;
- `GET /api/airspace/summary` — статистика нормативного справочника;
- `GET/POST/PUT/DELETE /api/airspace/zones` — поиск, импорт и ведение пользовательских зон;
- `GET/PUT /api/airspace/authorities` — справочник контактов и порядка взаимодействия с ОрВД;
- `POST /api/missions/optimize` — расчёт трёх планов;
- `GET /api/missions` — история сохранённых расчётов;
- `GET /api/missions/{id}/export?format=kml|geojson|gpx&plan=economy` — выгрузка маршрута выбранного плана;
- `WS /api/telemetry/ws` — демонстрационная телеметрия;
- `GET /api/health` — состояние сервиса и интеграций.

Интерактивная документация API доступна на `/docs`.
